00

Launch

Run the dev client from the mod project directory:

PS> cd NeoForge\projects\xeltacraft
PS> .\gradlew.bat runClient

Use a Survival world for most tests below — several scenarios specifically exercise inventory/material checks that Creative mode bypasses. Keep /gamemode creative handy for §5.1.

01

Auth

The Terminal reads its token from a mod-config value, not from the in-game login screen — the two are separate stores. This guide exercises the path the Terminal actually uses.

> /xeltacraft loadtoken C:\Users\GCV\AppData\Local\Temp\claude\c--Users-GCV-Desktop-minecraft\e2db2065-a941-43e6-8d4e-e3e423793f58\scratchpad\xelta_token.txt
> /xeltacraft balance
> /xeltacraft status
Expected

balance prints your real Xelta credit total. Delete the scratch token file once done — it's plaintext on disk. If balance fails with 401/403 after 2026‑08‑16, that's an expired token, not a bug.

02

Generation + item delivery

Confirms the full round trip: a prompt in the Terminal GUI becomes a real, retrievable item in your inventory.

Give yourself a Terminal, place it, open the GUI, enter a prompt (e.g. "a red sports car"), leave mode on Photo Lab, click Generate.

> /give @p xeltacraft:xelta_terminal
Expected

A Photo Slide item appears in the output slot once the job completes — take it into your inventory and check its tooltip carries the image URL/prompt.

03

Not a regression to chase — confirm the current (limited) behavior matches what's documented.

Expected (current behavior, unchanged)

A generic item icon, or "No Preview Generated" text if the slot is empty. Don't file this as a regression — it's a documented gap this pass didn't touch.

04

Media Canvas

The one place a real image preview genuinely works end to end.

> /give @p xeltacraft:media_canvas
Expected

Place it and feed it a generated image URL — the block face renders the downloaded image as a live texture. Skip .mp4 URLs; video isn't supported here.

5.1Creative mode — pre-flight skipped entirely

> /gamemode creative
Expected

Build proceeds immediately, no material check of any kind.

5.2Survival, empty-handed — abort with a real report

Clear stone bricks / cobblestone / stone / spruce planks / oak logs / oak stairs from your inventory, then run "a small medieval tower".

Build aborted — missing materials for this blueprint:
• 12x stone_bricks — Mine stone_bricks or cobblestone
• 4x oak_log — Mine oak_log
• 4x spruce_planks — No known ore/block source — obtain directly.
Gather these and try again, or switch to Creative mode.
Expected

No blocks placed. Counts vary with structure size — the point is a concrete, actionable list instead of a silent or mid-build failure.

5.3Survival, fully stocked — build proceeds

> /give @p minecraft:stone_bricks 64
> /give @p minecraft:cobblestone 64
> /give @p minecraft:spruce_planks 64
> /give @p minecraft:oak_log 64
> /give @p minecraft:oak_stairs 64
Expected

No abort message. Blocks place tick-by-tick as before; inventory visibly decreases.

5.4Survival — the crafting/smelting chain, not just a flat swap

Vanilla: stone_bricks crafts from 4× stone; stone itself is smelted from cobblestone. Give only the raw material:

> /give @p minecraft:cobblestone 64

No stone, no stone_bricks, no oak_log, no spruce_planks. Run the tower prompt again.

Expected

stone_bricks reads as covered — resolved through the crafting→smelting chain down to the cobblestone you hold — while oak_log/spruce_planks still show missing (unrelated to cobblestone). Stock those two alongside the cobblestone and the whole plan should report sufficient, confirming the solver chained both recipe types correctly instead of doing a flat 1:1 swap.

5.5Known limitation — read before filing a bug

Not a bug

The §5.4 case happens to work at execution time too, because VirtualCrafter already hardcodes that exact pair. For a chain only the new solver knows, the pre-flight can pass and the build can still halt mid-way. Fixing it means routing BuildStateManager's per-block substitution through CraftingDependencySolver instead of VirtualCrafter — flag it if you want that done.

08

Known gaps — not in scope, don't re-report

  • No image/video thumbnail in the Terminal Preview panel or Gallery tab (§03).
  • History tab has no filter/search/delete.
  • Uploads/downloads have no progress reporting or resume support.
  • No user-facing "retry failed job" action.
  • Auth split-brain: XeltaLoginScreen session vs XeltaCraftConfig.API_KEY are still two separate stores (§01 deliberately uses the config-based path).
  • Mining/Smelting planners are advisory-only by design — nothing mines or smelts automatically.
